# Desktop app

Extends [root instructions](../../AGENTS.md). Desktop package name is `voidra-project`, app ID `dev.voidra.project`, product name Voidra Project. App data uses `voidra-project`; never reuse the legacy `voidra` directory.

- `src/main/` owns windows, native dialogs/menus, preferences, protocol and service supervision. `src/project-service/` runs one utility process per project and owns native SQLite, the debounced `.voidra/` watcher and rebuildable action/run/profile/idea cache. Project work uses the shared format package; no duplicate format/lifecycle rules.
- `src/preload/` bundles to sandbox-compatible CommonJS. Expose only validated requests, checked responses, stripped subscription payloads and unsubscribe functions. Never expose Electron objects, IPC events or arbitrary channels.
- `src/shared/bridge.ts` is the zod/TypeScript boundary. Validate sender/main frame, arguments, utility messages and returned data. New bridge commands must stay narrow. Utility request correlation uses requestId independently from action/run IDs.
- `app/` exports static Next.js pages; `src/renderer/` contains the client shell and UI. No Next server or runtime port. Frontend dependencies are build dependencies; runtime native dependencies are packaged separately.
- Use storylens dashboard Ink & Iris tokens, Inter Variable and Lucide. Browser support is the pinned Electron Chromium runtime; native dialog closedby is supported. Do not add general-browser fallbacks or a second design system.
- HTML is served with the saved effective theme before paint and a CSP of local assets plus exact bootstrap script hashes. No unsafe-inline/eval, remote scripts, frames or popup/navigation permissions.
- Unit/native tests are in `tests/`; real Electron tests opt into source-mapped subprocess V8 coverage. Direct stripped-TS subprocesses do not preserve offsets and must not pollute that report. Keep 80% main/service gates and 90% format/standards gates.
- `e2e/` launches the built app with disposable data. Only the OS chooser is substituted; clipboard checks use the real Electron clipboard; actual files, IPC, windows and utility processes remain real. Axe legacy mode is necessary because Electron cannot create an auxiliary browser target; there are no cross-domain frames, which CSP forbids.
- `make setup` rebuilds SQLite for Electron's ABI. `make dev` opens the exported app; `make e2e` checks workflows/axe. `make package-dir` and `make smoke-packaged` verify unsigned arm64 output and SQLite loading inside the package.

- Run helpers come from `tools/run-engine`. Prepared operations and unfinished results hold the previous complete index. Reviews carry exact displayed action/run fingerprints into expected-hash writes. Recovery UI copies agent commands; it never writes implementation Git history or reconciles the Git index.
- The utility loads bundled templates through `voidra`, detects manifests/source filenames without reading code, and atomically creates planning data. Profile edits carry exact displayed block hashes; confirmed changes create draft actions. Keep all renderer controls labeled and preserve inferred/confirmed/assumed/open status and source evidence.
- Backlog and action editors call the shared package, carrying displayed file revisions. Board filtering/grouping is local view logic; lifecycle stages and blocker/completion rules come from the package. Cache plan bodies with actions, preserve complete snapshots during operations and keep invalid identity diagnostics visible. Git identity is read only.
- Question rounds and plan bodies are cached with actions (index version 8). Inbox counts are derived from records. Gate commands may resolve stale approval/review diagnostics but refuse other invalid data and unfinished work. Show effective Plan after stale approval without modifying files from an index read; all decisions carry displayed revisions.
- Package the arm64 process helper outside asar and keep preload free of Node-dependent imports.

Keep [desktop architecture](../../docs/architecture/desktop.md), [design system](../../docs/design-system.md) and evidence current. `CLAUDE.md` only imports these instructions.

- Keep the shell bounded to the window height, with independently scrolling navigation/main/Actions/Waiting regions and titlebar history/panel controls. Do not restore the removed workspace topbar or Local project label. Native-titlebar windows retain the compact titlebar accessory. Settings has keyboard-operable General/Appearance/Team tabs. Custom titlebar defaults on; snapshots separate its saved preference from each window's actual mode, and changes apply to new windows. Renderer window controls are a fixed validated action set targeting only the sender's own window; keep controls outside the titlebar drag region.

- Failed workspace mutations send a refresh event after the error response so stale revisions reload even if the watcher coalesces an edit. Preserve hash guards and bytes; failed reads must not trigger a refresh loop.

- The Run picker uses package eligibility from the snapshot. Queue replacement carries displayed queue/action hashes through the validated bridge; Profile draft activation remains an explicit action-page decision. Keep reorder controls keyboard operable and state live.

- Commit links come from actual Git trailer history, including untagged history retained for Sync. Main opens only current service-verified GitHub commit URLs. Planning commits carry an exact displayed preview and selected paths; use the Node-only helper and its explicit recovery results. Never include private planning files or expand selection to intake glossary/instructions.

- Conflicted action files use diagnostic projections with disabled edit/queue controls. Do not parse them as valid cached actions. Keep conflict guidance and refresh live after an editor save or pull; unrelated valid records can still be edited through the shared scoped-write contract.

- Every project command is classified in `workspaceEdits`; every planning mutation runs through `UndoHistory.perform` and the shared writer observer. Undo bodies/logs live in local SQLite, survive index schema rebuilds and reconcile private write receipts after restart. Keep Git operations outside undo. Replay rechecks persistent consumed records and current hashes under the writer lock; never bypass this for cleared locks or interrupted runs. History corruption clears only history tables and reports the loss.

- Decisions use the utility's rebuildable FTS5 projection; never persist copies of source decisions in planning files. Watch `docs/` and `GLOSSARY.md` as well as planning files. Keep pending delegated choices and stale approvals visible. Assumption revisits carry source revisions through the classified undo boundary. Document reads/editor opens use the package's contained, symlink-refusing Markdown path checks; the renderer gets only checked document data. Keep glossary/docs read-only and show missing or unreadable sources. See [knowledge architecture](../../docs/architecture/knowledge.md).

- Releases/candidates use the rebuildable cache; creation carries displayed member hashes through the classified history command. The private release-selection token is read for concurrency guarding and excluded from new undo bodies; tolerate existing token history entries. Render the selected work/version/tag/notes at Review and renew acceptance after any proposal change. App creation and acceptance perform no version/Git effects. See [release architecture](../../docs/architecture/releases-sync.md).

- Sync suggestions come from actual outside commits since a reachable Sync revision. Use the bounded validated snapshot and existing command-copy bridge; Sync runs in the coding agent. Watch Git and planning changes to refresh the suggestion. Persisted Sync consumption blocks earlier undo across restart, while a later app edit records the current run/Sync baseline.

- Optional AI uses main-only asynchronous safeStorage and OpenRouter HTTP; never return the stored key or expose network access to the renderer. Startup reads credential metadata without Keychain initialization. Utility AI queries select known public planning fields only, excluding source/docs/private/unknown data. Bind previews to exact context, validate feature/template outputs, use numeric progress and cancel by window/key changes. AI fills editable drafts, never auto-saves or approves. Keep native nested-dialog close/cancel events scoped to their own element. See [AI architecture](../../docs/architecture/ai.md).

- Bundled skill installation belongs to main and exposes only complete-bundle operations for a fixed client. Build markers from declared metadata and complete content; refuse symlink paths, compare exact preview revisions and protect edited/unmanaged copies. Keep the first-run offer optional and persisted. The build catalog binds all bundled members; missing/extra/linked/changed members refuse installation. Batch apply carries the exact complete preview revision and reports completed/remaining copies after failure; retry always previews again. Internal per-skill apply remains protected and serialized inside the same queue. Tests use temporary homes through an unpackaged-only override; never install into the developer’s real home as verification. See [distribution architecture](../../docs/architecture/skills-distribution.md).

- Public update checks are main-owned, startup/daily and opt-out; never send project/key data. Render remote notes as plain text and bind downloads to the current canonical repository release. Unpackaged tests use localhost; development otherwise makes no automatic update request. Keep build/icon.svg and its PNG/ICNS exports synchronized with the delegated icon review. Disable electron-builder automatic publishing; DMG smoke must launch an independent copy after detaching its image. See [publication architecture](../../docs/architecture/publication.md).
- Button enabled/disabled opacity changes immediately with its semantic state; preserve contrast on every enabled frame. Workflow accessibility audits wait for completed async controls and actual modal dismissal/navigation, not an early watched-file heading. Wait for review/rejection completion before the next queue; a Release remains at Review after acceptance, so its stage label alone is insufficient. Keyboard focus/Enter must wait for enabled controls, unlike click auto-waiting. Native async refresh checks explicitly set their bounded wait; Vitest expect.poll otherwise defaults to one second.
- Use five-second read/status/knowledge deadlines, 30-second workspace edit deadlines and 60-second Git planning/recovery deadlines. Busy-state completion checks, including post-save workflow dialog dismissal, wait within the matching edit deadline; never weaken approval/hash guards. Disable inferred electron-builder publishers with publish=null as well as --publish never. Sidebar/creator versions derive from the aligned app/library version. Built-app skill-version assertions use the running app version, so valid release alignment does not fail against a hardcoded preview.
- Run quality and desktop end-to-end suites sequentially: native quality tests open real windows, and separate data folders do not isolate desktop focus, clipboard or CPU contention. Keep account/browser interaction separate from these suites.
- Native run-index polls use the five-second workspace-read deadline, including startup, prepared-state and finalized-state checks. On failure, retain per-read phase, duration, stage/status and diagnostics. Keep the separate watcher-notification latency test's explicit one-second budget; it measures a different contract.
- The default Tasks page uses the package's unified task projection, cached with complete snapshots in index version 8. Keep promoted idea provenance without duplicate cards, preserve legacy release absence and show lock/recovery/planning problems. Project release discovery returns only bounded package-version metadata; the source selector carries the displayed metadata hash through classified undo. Watch the selected contained package path and never send its contents to AI. See [Tasks architecture](../../docs/architecture/tasks.md).
- Task drag grips, keyboard arrows and Backlog/TODO buttons call `moveTask` through classified undo with displayed card hashes. Preserve release assignments and lifecycle state; never simulate runs, reviews or completion with column writes. TODO placement still respects queue eligibility. Keep unavailable/unfinished work guarded in both renderer and utility.
- Appearance workflow tests establish normal native bounds inside the current display's work area before testing maximize/restore, then refresh the renderer's initial snapshot. Do not assume the 1200×800 startup window is unmaximized on hosted displays. Failure diagnostics include actual bounds, available work area and native window state.
- Markdown viewers use the shared sanitized GFM policy; Markdown editors use `MarkdownEditor` with controlled source and a stable `documentKey` per logical editing session. Cursor/selection reveal is limited to intersected physical lines; never serialize rendered HTML or normalize untouched stored line endings. Main injects a fresh document style nonce for CodeMirror while preserving exact script hashes and the rest of CSP. Keep editable content explicitly keyboard focusable. Native-menu text history routes through the active editor before Electron's ordinary text fallback; Cmd/Ctrl+S in dialogs uses the existing enabled submit button and validation. See [Markdown editing](../../docs/architecture/markdown-editing.md).

- Main owns the private Team roster and project subsets in AppStore. Use stable local member IDs and the existing portable Name <email> assignment; never rewrite Git identity or historical assignments. Roster commands carry displayed revisions, and main derives the project from the registered sender window. Me defaults only inside the selected subset. Reuse the shared assignee adapter, preserve previous assignments and keep Settings tabs keyboard operable. [Team settings](../../docs/architecture/team-settings.md).

- General’s default coding client is an explicit persisted Claude Code/Codex preference, initially Codex. All operational command surfaces use it, and main rechecks it before clipboard writes. Do not infer it from installed files, expose an alternate command picker or interrupt an existing run on preference change. The two full-bundle installer entry points remain the explicit both-client exception. Segmented controls retain native radio keyboard behavior and a full pointer target; keyboard tests wait for enabled state after asynchronous preference saves.


- Every unfinished submission form uses `useFormDraft` (or the separate encrypted credential adapter), with one top navigation badge per whole draft. Retain invalid partial values, original revisions/context, mode and generated results; fresh capture defaults Agentic. Main owns private durable storage outside Git, undo and disposable indexes. Flush before normal exits and submissions; a failed flush leaves the form open. Footer dismissal controls use data-dialog-close so they share the asynchronous close boundary. Freeze submission inputs while awaiting acknowledgement; Settings flushes its own Team/credential scopes, and page/window exits flush all forms. Window/app closure uses the sender-bound flush acknowledgement before service disposal. Never restore pending network/submission effects or renew approval hashes. Settings recovery is read-only for removed targets; credentials expose metadata only. [Draft architecture](../../docs/architecture/form-drafts.md) and the [form inventory](../../plan-v1.1.0/form-drafts.md) must stay synchronized with new forms.
- Task creation's private submission UUID binds to a durable write receipt via the existing history observer. Retrying recovers the original result or refuses uncertain state; never place private draft IDs/text in shared planning records. Keep source-backed AI results bound to their original context/model and draft identity. Related question/plan sections need distinct sibling keys so reload cannot retain duplicate controls.

- Tasks replaces primary Backlog/Actions navigation while retaining original source IDs and detail/gate surfaces. Capture the original card revision for the entire pointer gesture; Escape/cancel sends no write. Keep pointer movement local, card props stable and columns grouped once; release filters never replace a filtered subset of the run sequence. Unavailable current versions cannot match unassigned tasks through the Current filter.

- Keep the Tasks board mounted behind its details, keyed by canonical project path. Stable navigation/notification callbacks keep memoized cards unchanged. Scope form test locators to the active dialog/detail when a retained hidden board has a same-named filter. The shell keeps workspace reads active and invalidates them on service events; detail mounts must not issue redundant reads. Release settings uses native summary activation and flushes its own draft scope before closing, retaining input on failure.

Preserve a failed proposed order for review. Run request add/remove is explicit; converted-mode reordering belongs to Actions and never drops blocked requests or replenishes consumed ones. Cache sequence snapshots atomically with task snapshots in index version 8. Include both private ordering paths in local undo; portable run ordering receipts block consumed replay without private canonical references.

- Main owns per-project layout patches and observed attention hashes, guarded by the registered-root context. Hash question content/context, not unrelated watcher revisions; completed human steps do not introduce attention. Keep memoized board/Actions/Waiting content outside per-frame size updates and invalidate only the app snapshot for layout changes. [Panel architecture](../../docs/architecture/workspace-panels.md).

Counts and highlights share the sanitized visible-text traversal; preserve complete Markdown blocks in Decisions and Glossary. Directory layout uses private project preferences and the shared accessible splitter. See [knowledge architecture](../../docs/architecture/knowledge.md).
