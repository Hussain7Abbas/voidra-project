# Desktop app

Extends [root instructions](../../AGENTS.md). Desktop package name is `voidra-project`, app ID `dev.voidra.project`, product name Voidra Project. App data uses `voidra-project`; never reuse the legacy `voidra` directory.

- `src/main/` owns windows, native dialogs/menus, preferences, protocol and service supervision. `src/project-service/` runs one utility process per project and owns native SQLite, the debounced `.voidra/` watcher and rebuildable action/run/profile/idea cache. Project work uses the shared format package; no duplicate format/lifecycle rules.
- `src/preload/` bundles to sandbox-compatible CommonJS. Expose only validated requests, checked responses, stripped subscription payloads and unsubscribe functions. Never expose Electron objects, IPC events or arbitrary channels.
- `src/shared/bridge.ts` is the zod/TypeScript boundary. Validate sender/main frame, arguments, utility messages and returned data. New bridge commands must stay narrow. Utility request correlation uses requestId independently from action/run IDs.
- `app/` exports static Next.js pages; `src/renderer/` contains the client shell and UI. No Next server or runtime port. Frontend dependencies are build dependencies; runtime native dependencies are packaged separately.
- Use storylens dashboard Ink & Iris tokens, Inter Variable and Lucide. Browser support is the pinned Electron Chromium runtime; native dialog closedby is supported. Do not add general-browser fallbacks or a second design system.
- HTML is served with the saved effective theme before paint and a CSP of local assets plus exact bootstrap script hashes. No unsafe-inline/eval, remote scripts, frames or popup/navigation permissions.
- Unit/native tests are in `tests/`; real Electron tests opt into source-mapped subprocess V8 coverage. Direct stripped-TS subprocesses do not preserve offsets and must not pollute that report. Keep 80% main/service gates and 90% format/standards gates.
- `e2e/` launches the built app with disposable data. Only the OS chooser is substituted; clipboard checks use the real Electron clipboard; actual files, IPC, windows and utility processes remain real. Axe legacy mode is necessary because Electron cannot create an auxiliary browser target; there are no cross-domain frames, which CSP forbids.
- `make setup` rebuilds SQLite for Electron's ABI. `make dev` opens the exported app; `make e2e` checks workflows/axe. `make package-dir` and `make smoke-packaged` verify unsigned arm64 output and SQLite loading inside the package.

- Run helpers come from `tools/run-engine`. Prepared operations and unfinished results hold the previous complete index. Reviews carry exact displayed action/run fingerprints into expected-hash writes. Recovery UI copies agent commands; it never writes implementation Git history or reconciles the Git index.
- The utility loads bundled templates through `voidra`, detects manifests/source filenames without reading code, and atomically creates planning data. Profile edits carry exact displayed block hashes; confirmed changes create draft actions. Keep all renderer controls labeled and preserve inferred/confirmed/assumed/open status and source evidence.
- Backlog and action editors call the shared package, carrying displayed file revisions. Board filtering/grouping is local view logic; lifecycle stages and blocker/completion rules come from the package. Cache plan bodies with actions, preserve complete snapshots during operations and keep invalid identity diagnostics visible. Git identity is read only.
- Question rounds and plan bodies are cached with actions (index version 6). Inbox counts are derived from records. Gate commands may resolve stale approval/review diagnostics but refuse other invalid data and unfinished work. Show effective Plan after stale approval without modifying files from an index read; all decisions carry displayed revisions.
- Package the arm64 process helper outside asar and keep preload free of Node-dependent imports.

Keep [desktop architecture](../../docs/architecture/desktop.md), [design system](../../docs/design-system.md) and evidence current. `CLAUDE.md` only imports these instructions.

- The Run picker uses package eligibility from the snapshot. Queue replacement carries displayed queue/action hashes through the validated bridge; Profile draft activation remains an explicit action-page decision. Keep reorder controls keyboard operable and state live.

- Commit links come from actual Git trailer history, including untagged history retained for Sync. Main opens only current service-verified GitHub commit URLs. Planning commits carry an exact displayed preview and selected paths; use the Node-only helper and its explicit recovery results. Never include private planning files or expand selection to intake glossary/instructions.

- Conflicted action files use diagnostic projections with disabled edit/queue controls. Do not parse them as valid cached actions. Keep conflict guidance and refresh live after an editor save or pull; unrelated valid records can still be edited through the shared scoped-write contract.

- Every project command is classified in `workspaceEdits`; every app mutation runs through `UndoHistory.perform` and the shared writer observer. Undo bodies/logs live in local SQLite, survive index schema rebuilds and reconcile private write receipts after restart. Keep Git operations outside undo. Replay rechecks persistent consumed records and current hashes under the writer lock; never bypass this for cleared locks or interrupted runs. History corruption clears only history tables and reports the loss.

- Decisions use the utility's rebuildable FTS5 projection; never persist copies of source decisions in planning files. Watch `docs/` and `GLOSSARY.md` as well as planning files. Keep pending delegated choices and stale approvals visible. Assumption revisits carry source revisions through the classified undo boundary. Document reads/editor opens use the package's contained, symlink-refusing Markdown path checks; the renderer gets only checked document data. Keep glossary/docs read-only and show missing or unreadable sources. See [knowledge architecture](../../docs/architecture/knowledge.md).

- Releases/candidates use the rebuildable cache; creation carries displayed member hashes through the classified history command. The private release-selection token is read for concurrency guarding and excluded from new undo bodies; tolerate existing token history entries. Render the selected work/version/tag/notes at Review and renew acceptance after any proposal change. App creation and acceptance perform no version/Git effects. See [release architecture](../../docs/architecture/releases-sync.md).

- Sync suggestions come from actual outside commits since a reachable Sync revision. Use the bounded validated snapshot and existing command-copy bridge; Sync runs in the coding agent. Watch Git and planning changes to refresh the suggestion. Persisted Sync consumption blocks earlier undo across restart, while a later app edit records the current run/Sync baseline.

- Optional AI uses main-only asynchronous safeStorage and OpenRouter HTTP; never return the stored key or expose network access to the renderer. Startup reads credential metadata without Keychain initialization. Utility AI queries select known public planning fields only, excluding source/docs/private/unknown data. Bind previews to exact context, validate feature/template outputs, use numeric progress and cancel by window/key changes. AI fills editable drafts, never auto-saves or approves. Keep native nested-dialog close/cancel events scoped to their own element. See [AI architecture](../../docs/architecture/ai.md).

- Bundled skill installation belongs to main and accepts fixed agent/name operations only. Build markers from declared metadata and complete content; refuse symlink paths, compare exact preview revisions and protect edited/unmanaged copies. Keep the first-run offer optional and persisted. Tests use temporary homes through an unpackaged-only override; never install into the developer’s real home as verification. See [distribution architecture](../../docs/architecture/skills-distribution.md).
