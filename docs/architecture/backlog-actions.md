# Backlog, actions and slices

[Architecture index](Intro.md) · [Format API](../format/api.md) · [P06](../../plan/phase-06-backlog-actions-and-lifecycles.md)

The backlog creates and edits new, needs-info, ready and rejected ideas. Rejection requires a reason. Promotion atomically writes an action and reciprocal links, using the selected type's engine-defined first stage. Rejected and already-promoted ideas cannot be promoted again; reopening is an explicit edit. Existing unknown fields survive edits.

The shared package supplies creation, editing, promotion and checklist operations. All use whole-project validation and expected hashes, and write planning files only. The app refuses mutations during active or unresolved runs/operations. Description conflicts expose reload and an explicit overwrite of current description bytes; stale metadata is not restored. Cycles and missing references fail before any target write. Cancellation preserves the action and its history and removes it from the personal queue. Human cancellation preserves unchecked steps rather than pretending they were completed.

A human task has steps and no agent stages. Its last completed step completes it unless child slices remain. Done human tasks unblock agents. Blocker records are hash-guarded when queueing and starting; run-start consumption includes dependencies. A cancelled blocker remains unfinished. Parents are also blocked while children remain unfinished.

Aggregate parents finish only when every child is Done/Released or a completed human task. A parent with its own implementation retains its own Review; a parent with plan files retains exact plan approval. An aggregate parent with no own work or plan uses `completedBySlices: true`, preserving the individual child gates. Human cancellation and aggregate completion without a parent plan require metadata advertising voidra 0.2.0. The format remains 1, existing valid projects remain readable, and older clients give the minimum-reader notice. The strengthened parent check enforces the vision's existing completion rule; it does not repair files silently.

The SQLite index is a disposable version-7 cache for actions, runs, profiles and ideas; plan bodies and question rounds are cached with their action. Invalid identities are excluded from unique-key inserts and their diagnostics remain visible. Prepared writes retain the previous complete cache. Deleting the cache rebuilds from files.

The board filters type, status, assignee and who does the work. Cards sit in their own stage; child cards carry parent context in that stage. Text marks blocked work. Action pages show a stage timeline, source-preserving Markdown editing in place, plans, run results, dependencies, child slices, links and checklists. Markdown uses the shared sanitized GFM viewer and active-line source editor; [Markdown editing](markdown-editing.md) defines source coordinates, exact text history and the style nonce. A reversible library selection does not meet the ADR bar by itself. The layout follows Ink & Iris. P08 removes blanket content-visibility from the board after a CI contrast failure; columns remain reachable and consistently styled without deferred subtree rendering. P17 measures large-project performance before introducing any further rendering optimization.

Git identity is read with Git's effective project configuration. Missing name/email is explained and work can stay unassigned. No Git write is performed here. P07 supplies the question/plan/review gates and inbox, P08 expands skill execution beyond Docs/chore, P09 adds planning commits and richer queue coordination, and P10 adds persisted undo.

Profile change drafts are activated by the explicit **Activate and queue draft** action. It carries the displayed action-file revision; absent or stale revisions are refused. Activation and queueing happen together and record the person and timestamp. The standalone agent refuses an unactivated draft. An unchanged sibling stale gate remains visible while fresh actions can be queued; the affected action still needs its own current approval.

Conflicted action files appear as explicit diagnostic projections with status Conflicted, rather than valid indexed records. Their edit/queue controls are disabled. Other valid records remain editable; shared writes retain the conflict diagnostics, refuse new broken references and stop on conflicts that arrive during a write. Resolve markers outside the app; the watcher replaces the projection after the saved record validates. A real teammate push/pull also refreshes action details without restarting.


The v1.1.0 capture surface is shared by Action and Backlog creation. It defaults fresh sessions to Agentic, offers Normal with optional AI-generated titles, uses Team assignment and has no work-performer selector. Existing human records retain their semantics. Backlog proposed types and portable assignments survive editing and promotion; adding them advertises reader 1.1.0 independently of task-tracking opt-in. Description/dependency editors and review feedback use [private drafts](form-drafts.md), retaining original revisions through restoration. Creation also carries a private submission UUID bound to the durable grouped-write receipt so retrying a lost acknowledgement does not create another task.
