# Desktop architecture

[Architecture index](Intro.md) · [Design system](../design-system.md)

Native run-index tests read the full workspace through main/utility IPC; these reads recompute the snapshot from disk, rather than only waiting for a watched event. Their bounded polls use the service's five-second read deadline. Finalization must expose Review and its commit only after pending diagnostics/recovery and ownership clear. Failure logs retain each sampled phase, read duration, stage/status and diagnostics. The separate watcher test keeps its explicit one-second notification budget; that latency assertion is not relaxed by the run-index correction. See [CI reliability evidence](../verification/run-index-ci.md).

Main reads the persisted `customTitlebar` preference (default true for fresh and older settings) when constructing each BrowserWindow. Custom mode is frameless and uses a renderer titlebar; native mode uses the OS frame. Snapshots distinguish the saved preference from this window's actual mode, so changing the switch does not hide necessary controls before reopening. The narrow `window-control` bridge accepts only close, minimize and toggle-maximize for the trusted sender's own window; the renderer cannot choose a window ID. Maximize/fullscreen events refresh the restore label. Native settings changes apply to newly opened windows, without restarting services or discarding renderer edits.

`apps/desktop` builds a static Next.js renderer and three Electron bundles: main, sandboxed CommonJS preload, and utility project service. The renderer is served only from `app://voidra-project/`; there is no HTTP server. Protocol resolution canonicalizes assets and rejects origin/path escapes. CSP allows local assets and exact hashes of trusted generated bootstrap scripts. Renderer Node integration is disabled, context isolation/sandboxing enabled, permissions denied, and navigation/popups blocked.

The bridge validates request/response/event shapes with zod. Main-process handlers verify the sender is the trusted top-level frame. OS folder selection is a narrow command; opening from recents is limited to existing saved paths. The renderer never gets filesystem, shell or raw Electron/IPC objects. TanStack Query caches snapshots and invalidates them on project/theme/service events. Failed workspace mutations also emit a changed event: an exact-revision rejection may have observed newer source than the screen, so refresh does not depend on another file-watcher notification. Failed workspace reads and knowledge queries do not emit this event, preventing an error/refetch loop.

One utility process owns each project's native SQLite connection. Main supervises it, reports a stopped connection and attempts bounded restart; a manual reconnect resets that budget. Status/workspace/knowledge reads retain a five-second deadline; workspace mutations have 30 seconds for guarded writes and post-write indexing, while Git planning/recovery keep 60 seconds. Readiness/completion checks use the matching operation boundary and preserve exact-revision guards. Sidebar and newly initialized creator metadata use the aligned runtime/library version. Graceful shutdown closes SQLite and flushes native coverage in test runs. Separate utility processes isolate failure and keep future indexing work out of the window thread. See [the process ADR](../adr/2026-10-13-utility-process.md).

Canonical project paths map to one window; in-flight opens are coalesced. A second instance forwards its requested folder to the running app. Recent folders and appearance persist atomically under the app's own data directory. Missing folders offer Locate/Remove; removing a shortcut leaves project files untouched. The project utility validates and indexes planning records and watches live changes. Tasks, Actions intent, profile and inbox share its snapshots; unresolved writes/runs preserve the preceding complete index.

SQLite must be rebuilt for Electron's ABI, even though host/Electron share a Node major. CI launches the real exported app, checks keyboard/axe behavior, creates an unsigned arm64 directory package, then starts that packaged executable and checks SQLite through its real utility service. UI/preload execution is covered by end-to-end behavior; no percentage target is imposed on renderer components.

Primary references: [Electron security](https://www.electronjs.org/docs/latest/tutorial/security), [utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process), [Next static exports](https://nextjs.org/docs/app/guides/static-exports), and [axe integration limitations](https://github.com/dequelabs/axe-core-npm/blob/develop/packages/playwright/error-handling.md).

The service reads real Git trailers and watches HEAD, refs and index alongside planning files. Commit links are validated in the service snapshot and rechecked by the main process before opening GitHub. The Run picker persists displayed queue/action revisions through a narrow bridge. Planning commits preview exact paths and exclude private files; their Node-only journal/recovery helper keeps Git index effects out of the renderer and preserves unrelated staging.

App edits are wrapped by the service's `UndoHistory`, with an exhaustive bridge command classification. Its local SQLite tables retain labels, times, SHA-256 body references and baseline run identities; index schema changes leave these tables intact. Prepared edits and replay attempts reconcile against durable grouped-write receipts. The history engine restores exact bytes through the package writer, checks persisted consumption before work starts, and binds outside-overwrite confirmation to the current file hashes. [The undo ADR](../adr/2026-10-13-undo-history.md) sets the 100-operation/32 MiB payload limit and explains recovery/corruption boundaries.

The Decisions and Glossary screens use narrow correlated knowledge reads from the project utility. Repository docs render safely in an app dialog or open in the editor through a contained path check. See [knowledge architecture](knowledge.md).

The v1.1.0 description editor uses a fresh main-generated style nonce per HTML document to authorize CodeMirror style installation. Script authorization remains exact bootstrap hashes. See [Markdown editing](markdown-editing.md) for source preservation, native text history and accessible cursor/selection rendering.

The complete task/sequence projection uses disposable index version 8. Sequence intent, pending requests, dependency warnings and exact conversion preview are rebuilt through shared APIs and saved in the same transaction as actions/tasks. Unfinished operations retain the prior complete cached sequence. The renderer receives no filesystem capability or actor/path override; conversion/reorder are classified persistent-history commands.
