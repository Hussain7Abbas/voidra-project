# Private form drafts

[Architecture index](Intro.md) · [v1.1.0 form contract](../../plan-v1.1.0/form-drafts.md)

The Electron main process owns `userData/form-drafts/`. Canonical project paths select hashed project directories; renderer requests cannot supply a project path. Draft UUIDs select individual files. The store is independent of the rebuildable SQLite index, project Git files and canonical undo history. Files use mode 0600, serialized expected-revision writes, temporary-file replacement and file/directory synchronization. Linked files and directories are refused. Invalid saved files remain untouched and are reported alongside readable drafts.

A draft contains its form family, target, complete partial values, original source revisions, creation/update timestamps and a display excerpt. Canonical validation happens only on explicit submission; draft persistence allows incomplete or invalid input. Reads of legacy version-zero drafts supply Normal mode in memory. Only an explicit subsequent save upgrades their bytes.

The renderer's shared form session owns one complete value object and a stable draft ID. Input updates enqueue private saves. The top navigation restores a whole draft, starts a fresh session or explicitly discards the current session. A restore does not submit a command, regenerate AI output, replay a pending request or renew a source revision. A fresh task session starts Agentic; a restored task uses its saved mode.

Native dialog dismissal waits for draft flush, including Escape and light dismissal. While flushing, the native close watcher is disabled and the dialog is inert; errors restore focus and remain visible in the open dialog. Footer Cancel/Done controls use the same asynchronous close path as the header, Escape and backdrop. Submission freezes inputs until acknowledgement. Settings closes after flushing its Team and AI preference forms; page, project and window exits flush all mounted forms. This uses the pinned Chromium [dialog close behavior](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element) and [close watcher request](https://html.spec.whatwg.org/multipage/interaction.html#request-to-close-a-close-watcher), rather than asynchronous unload handlers. Window/app close uses a sender-bound flush request and acknowledgement before service disposal. The renderer temporarily makes the document inert during that final flush; failure leaves the window available for recovery.

AI model/effort inputs use ordinary private `ai-settings` drafts, separately targeted to each coding client. Restoring them never applies preferences or sends a prompt. The removed provider’s encrypted key drafts are deleted without decryption at startup; no credential form remains.

Task capture uses the main-only headless coding-agent service with only the supplied form text, no project sources. Normal's blank title requests a bounded title; its description/type remain user supplied. Agentic requests a bounded title, Markdown description and valid action type. The privacy preview precedes generation; generated metadata stays in the draft until a separate explicit Save. Each mode retains its own input and generated result. Changing a mode’s content invalidates that result; Agentic metadata seeds untouched Normal fields without overwriting explicit edits. Saving/reading an unfinished draft alone makes no AI request.

Task creation carries the private draft UUID as its submission identity. The utility records a private request fingerprint and the shared writer operation ID before canonical replacement, then records acknowledgement after the durable writer receipt. Retrying the same submitted values recovers the existing result across restart; different values, interrupted operations and uncertain outside edits refuse blind recreation. These receipts live outside the disposable project index, contain hashes rather than form text, and add no draft identity to shared planning records. Undo keeps its existing observer and consumption guards.

All inventoried form families now have adapters, including source-bound question/feedback, setup/answers, Team, AI review/follow-up, planning commit and release selection. Read-only Settings recovery keeps removed-target text accessible and copies raw Markdown through a UUID/revision-checked main command; AI preference drafts have the same whole-form recovery as other non-secret forms. Question drafts retain action/round/question context, planning commits retain their exact displayed preview and operation ID, and release selection retains original member hashes. The [inventory](../../plan-v1.1.0/form-drafts.md) lists the adapters. Validation evidence is recorded under [P04](../verification/v1.1.0-p04.md). A failed save offers an explicit separate-draft recovery without replacing the original session. Identical retries after a lost acknowledgement recover the durable revision; differing stale values refuse replacement. Process-death checks exercise both the synced temporary file and durable replacement boundaries.
