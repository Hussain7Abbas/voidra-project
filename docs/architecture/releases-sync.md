# Releases and outside work

[Architecture index](Intro.md) · [Release format](../format/release.md) · [Run architecture](runs.md)

P12 is complete; [its evidence](../verification/p12.md) records the shared package, desktop selection/Review, standalone planning/finalization, terminal intake, Sync and actual both-agent checks. V11-P09 will extend the existing flow with guided release choices and task target versions.

`releaseCandidates` derives completed, unreleased work from canonical actions and release records. Active selections reserve their members; cancellation releases the reservation. `createReleaseAction` takes displayed hashes and creates a ready Release at Plan, preserving member bytes and linking selected IDs. A private selection token prevents concurrent requests from claiming the same work; public actions remain authoritative. Pending runs/writes and invalid planning data refuse creation. New selections advertise reader 0.2.0.

The version-7 SQLite projection caches releases and candidates, retains complete snapshots during prepared writes and preserves undo tables during rebuilds. The app lists notes, included actions and tags. A labeled checkbox dialog creates an action through classified history; new undo bodies exclude the private selection token because it is serialization bookkeeping, so an unrelated terminal release does not prevent undo. Locks and recovery journals remain outside history.

Structured Releases carry selected IDs, proposed version and tag. The versioned proposal record must match. `readPlan` retains exact hashes of all three plan files and extends the displayed revision with selection and record metadata/body. Final status/date are bookkeeping; version, tag, members and notes remain fixed. Review fingerprints and grouped guards include the record and selected action files. Changed proposals require new acceptance. The app displays the proposal and leaves acceptance at Review/Ready for the agent. Accepted release plans/notes also enter the decision projection.

The app creates no version bump, commit or tag. The runtime binds prepared files, members, version/tag and commit message in its private checkpoint. It uses a separate Git index, reuses matching run-trailer commits/tags and refuses conflicting tags or changed files. Release/members/run/checkpoint change in one durable group; verified dead-owner recovery reconciles this run’s prepared operation before Git/index effects. Prepared approved Release intent can resume its commit. Terminal intake collects and queues eligible work atomically with real Git identity. Sync behavior follows below.

Version re-planning retains the consumed prior draft as superseded history instead of deleting it. That history no longer reserves work and is visibly labeled Superseded.

Sync is implemented in the shared package and a Node Git adapter. It chooses a reachable sync revision, reads actual trailers, verifies the exact report HEAD/range and guards template values/profile hashes. Confirmed values remain protected. One durable group writes profile/proposals/record and consumption with a private serialization token; dead-owner retries recover only contained Sync receipts and preserve outside edits. The desktop reads a bounded outside-commit count and copies either agent’s Sync command, refreshing on existing Git/planning watchers. The index remains disposable; undo consumption persists in shared Sync records.
