# Skill installation and release copies

[Architecture index](Intro.md) · [Folder research ADR](../adr/2026-10-14-bundled-skill-installer.md)

The desktop build copies six self-contained Voidra skills, including generated runtime/native/template assets and the AGPL license. Each SKILL.md declares its independent skill version and written format. Build-time validation creates `voidra-skill.json` with version, format and a hash of paths, file bytes, executable flags and directories. The installed marker itself participates in preview revisions. The build also writes `voidra-bundle.json`, listing the complete catalog and each bundled tree revision. Missing, extra, linked or changed catalog members refuse bundle preview/status instead of silently shrinking the installation. No coding-agent CLI or network access is needed for desktop installation.

Main installs separate user copies into `~/.claude/skills` and `~/.agents/skills`, as confirmed in the ADR. It never replaces an agent's complete skills directory or touches project source/configuration. Settings → General has exactly two installation entry points: **Install Claude Skill n/6** and **Install Codex Skill n/6**. Each installs the complete catalog for that client; the numerator counts present, unedited, unblocked copies matching the bundled version/format, and the denominator comes from the validated catalog. The section shows only the two counted buttons, with concise outcome/error feedback after an operation. Per-skill diffs appear only in the required replacement review, rather than as permanent Settings details. Status loads when Settings opens; every Install click obtains a fresh filesystem preview, including external edits. There are no individual-skill install/remove choices. A nonmodal setup offer is saved as acknowledged after dismissal or opening its installation review; restart does not repeat it.

An update materializes validated bundle bytes into a complete staged copy (including real asar inputs; Node recursive cp does not copy virtual archive directories) before moving the old folder aside. Copy failures preserve the old installation; a failed placement restores its backup. Symlink destinations/parents/payload entries and unsupported file kinds are refused. A private in-process queue serializes app mutations. Every apply compares the exact displayed installed and bundled revisions again after staging. Edited or unmanaged copies require explicit confirmation before replacement; the underlying checked per-skill implementation retains removal for internal API compatibility. Small text changes show a unified replacement hunk; binary/large changes show file hashes. Large total previews are labeled truncated and remain bound to the complete content revision. Other skill folders and the other agent's copy are preserved.

The validated bridge exposes status, complete-bundle preview/apply and offer dismissal. Apply accepts only the fixed client, exact bundle revision and confirmation; main recomputes every catalog member. The previous individual-skill bridge operations are removed. Home selection is main-owned; only unpackaged test builds accept a disposable home override. The renderer cannot provide arbitrary target paths. The current project format comes from the utility's workspace projection.

The same in-process queue serializes a full batch against other installer mutations. It checks every member before starting and again per copy. A partial failure reports completed and remaining names, leaving each completed copy valid and each failed copy restored. A new preview safely resumes after restart, with no overwrite of newly edited content. A stale review renews the displayed diff but never applies it without another explicit confirmation. No batch failure removes unrelated skills or changes the other client.

`make skills-sync DRY_RUN=1` previews the release against an isolated clone of `Hussain7Abbas/voidra-skills`, or a clean `SKILLS_REPO=/absolute/clone`. It selects actual skill folders, rejects linked payloads, copies licenses/templates, preserves unrelated catalog entries, and validates every staged skill plus the complete destination catalog before any push. The dry run prints the actual binary-capable diff and exact changed paths; the requested clone and remote are unchanged.

A real sync uses the distribution repository's own `make validate` and `make publish SKILL=<name>` for each skill. Each committed/pushed skill change touches only that folder. Shared templates/catalog/docs/instructions publish afterward in a separate commit; outgoing shared changes never enter single-skill publishing history. Failure stops subsequent publication and leaves a checkout for recovery. Repeating identical source produces no new commits. The CLI uses Hussain7Abbas's existing authentication and source Git identity without changing the active account or saving/printing a token. Public release synchronization runs in P17 after the matching library release; P14 verifies the genuine publishing implementation against local bare remotes and previews the public repository. No immediate skills.sh indexing is promised.

The pinned distribution CLI 1.7.0 still targets Codex's older global folder. Desktop installation deliberately uses current official folder guidance directly; terminal users should check their CLI version/destination. This boundary is a reason for owning exact offline copies in the app, rather than fetching/installing through npx.
