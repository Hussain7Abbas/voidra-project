# Workspace panels and attention

[Architecture](Intro.md) · [Desktop](desktop.md) · [Human gates](questions-gates-inbox.md) · [Drafts](form-drafts.md)

The shell contains independent Project navigation, main content, Actions and bottom Waiting for you regions. Undo/Redo and all panel controls live in the custom titlebar, outside its drag region. Native-titlebar windows use a compact accessory with the same history, panel and Settings controls. Panel/history controls sit together beside Settings, at the opposite end from the platform window controls. The title is independently centered on the full window; opaque control groups layer above it when space is tight. Panel toggles retain the same outline glyph and fill its represented pane while open, without an active background color. Their expanded/controlled semantics and attention count remain intact. There is no workspace topbar or Local project status label. The previous disabled Overview entry and primary Waiting page entry are removed; recovery remains reachable from the main Run/task surfaces.

Main owns per-project layout preferences in the existing atomic AppStore. A SHA-256 context derived from the registered canonical root (or welcome context) guards `set-workspace-layout`; the renderer cannot choose another destination. Narrow patches merge inside the serialized settings queue. They are separate from Git, canonical records, project Undo and form drafts. Unknown stored settings survive, while a malformed layout resets only that layout's known preferences. The snapshot exposes the current context and sanitized values. Local optimistic state stays stable during dragging; an unrelated snapshot cannot replace its preview. Persistence failures report an error.

Navigation defaults to 256px, Actions to 320px and Waiting to 280px. Each uses a pointer-captured splitter, arrow keys and Home/End through the same bounds; Enter hides its pane and moves focus to its titlebar control. Escape/cancellation restores the starting preferred size without a settings write. Pointer previews use animation frames, and persistence happens on release. Displayed sizes fit the current usable viewport, retaining 320px main width at the supported minimum window and 160px main height above Waiting. Resizing a window does not replace saved preferred dimensions. Hiding is an independent flag. All pane contents scroll independently.

The splitters follow the [WAI window-splitter pattern](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/): focusable separator, named controlled pane, orientation and current/minimum/maximum range values. Named resize-control regions contain splitters without nesting the main landmark. Native HR reset height is explicitly overridden for vertical controls. Pointer handles alone suppress selection/touch gestures; task/question text stays selectable. Titlebar, View menu and Cmd/Ctrl+Alt+1/2/3 share the same guarded toggle path. Renderer keyboard routing also covers Chromium-delivered key events; modal/composition/unavailable states retain their guards.

Waiting reuses the indexed inbox and existing source-bound question, exact-plan, review and checklist forms. Selecting an item opens its detail inside the panel with Back to Waiting for you. The panel stays mounted when hidden, retaining selection, source context and editor state; hiding first flushes drafts and refuses on failure. Restart uses the same private draft badges and original revisions. A restored value never submits or renews a gate. Full question/reason/option/answer Markdown uses the shared policy; compact button labels use sanitized phrasing-only Markdown with no nested navigation or input controls. Inferred prose is rendered too.

Attention identity follows actionable content: question round/text/options/reason, exact plan/review context, individual unfinished human steps and inferred answers. Unrelated action/question-file refreshes or completing an existing checklist step do not create new attention. Main stores only bounded SHA-256 tokens for currently observed attention in private layout settings. Resolved items leave that set without opening the panel; work that subsequently reappears can open it again. On the first encounter, existing actionable items open Waiting; unchanged dismissed items remain dismissed across refresh/restart. A newly observed item or changed actionable content opens it without focusing it or changing its selected form. Explicit user navigation may focus the selected detail; passive attention never takes typing focus.

The board and Actions/Waiting content have stable memoized boundaries. Per-frame divider movement changes their enclosing dimensions, avoiding repeated task-card construction or Markdown parsing. Layout notifications invalidate only the app snapshot, not the planning index. Actual workspace changes still refresh their own queries and preserve source/recovery guards.

## Agentic workflow follow-up

The Actions sidebar includes run ordering, explicit retries, planning commits and recovery; there is no separate Run page. Splitter layout occupies exactly the 1px resize line, with wider pointer hit targets positioned over adjacent panes. The yellow outside-change notification spans the app above workspace panes.

The project navigation order is Tasks, Documentation, Releases, Profile. Release settings and the release-aware task-tracking upgrade are on Releases; the Tasks board retains its release filter. Release-source drafts keep the same stable identity across this navigation change and still flush before closing the disclosure or leaving the page.
