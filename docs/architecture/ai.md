# Optional AI suggestions

[Architecture index](Intro.md) · [Agent workflows](../agents.md)

P13 is complete. Main owns an asynchronous encrypted credential store and the bounded OpenRouter HTTP client. `AiSettings` writes only encrypted key bytes into the app data directory with mode 0600 and atomic replacement; public settings return configured/available/model, never the saved key. Startup checks metadata only. Keychain initialization waits for explicit AI settings or use, so missing/invalid AI settings do not disable manual planning. Removing/changing the key cancels active requests.

The client uses authenticated `/models`, `/key` and streaming `/chat/completions`. It bounds responses, handles UTF-8/chunk/SSE framing and comments, requires completion, aborts cancellation/timeouts, and maps authentication/credit/rate/provider errors without forwarding raw server text. Requests cannot follow credential-bearing redirects. Model choice is explicit. The renderer neither stores the key nor performs network requests.

Project AI context comes through the same correlated utility-query boundary as knowledge, selected by record identities. The collector chooses only known public planning fields and bodies: selected profile answer, action/run, completed release members and proposal. Source files, repository docs, private queues/journals, unknown record fields and credentials are excluded. Onboarding question descriptors are validated configuration/UI text; user draft notes are explicit input. The main prompt boundary rejects outside/private/traversing source paths and caps total text. Each feature has a version-1 prompt and recorded fixture responses.

Preview fingerprints the exact selected context before sending it. Generation rechecks that fingerprint, uses one request per window and reports numeric progress without exposing provider output. Cancellation is scoped to the requesting window; key/model changes cancel all active calls. A provider echo of the saved key is rejected. Suggestions are parsed against feature-specific schemas and template answer types before being returned.

Native modal previews show the selected text and model; nested dialog events are scoped to their own target. Every AI control is hidden without a key. Settings are an optional disclosure so appearance changes do not initialize the Keychain. Errors/cancellation preserve the existing form. Edited idea/action suggestions fill fields; profile suggestions become confirmed only through the existing Save answer command (or Create planning folder during onboarding). Follow-up questions are editable local prompts for refining an answer, not automatic template/question-round mutations. Summaries remain labeled drafts. Release-note drafts open the existing description editor at Plan for explicit saving before agent planning; they cannot authorize a proposal, commit or tag.

The development-only test endpoint must be localhost; packaged builds always use OpenRouter. Tests use real temporary files and local HTTP servers. Desktop/native tests use Chromium's mock-Keychain switch with a fake API key; this is not a claim that a real OpenRouter account or a user's production Keychain was used.

Primary protocol references checked against the pinned environment: [Electron 44.7 safeStorage](https://github.com/electron/electron/blob/v44.7.0/docs/api/safe-storage.md), [OpenRouter models](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties), [current-key metadata](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key), [streaming](https://openrouter.ai/docs/api_reference/streaming), and [errors](https://openrouter.ai/docs/api_reference/errors-and-debugging). The unsigned macOS app may need renewed Keychain consent after an update; credential failures preserve the file and require explicit re-entry/removal rather than plaintext fallback.
