# Optional AI suggestions

[Architecture index](Intro.md) · [Agent workflows](../agents.md)

Internal AI prompts run headlessly through the installed Claude Code or Codex CLI selected in Settings. They use that agent's existing sign-in. Main owns subprocess execution; the renderer has no process, filesystem or network access. There is no OpenRouter client, key entry, model-list request or provider credential store. At startup the version-1 AI settings file is migrated to non-secret version-2 preferences without decrypting its obsolete key, and the removed provider's encrypted unfinished-key directory is deleted after rejecting linked directories. Unsafe linked paths are preserved. Invalid settings are preserved and reported without disabling manual planning.

`AiSettings` atomically stores a separate model and effort for each client in `ai-settings.json` (mode 0600). Settings and first-launch setup share the same labeled controls. A blank model uses the CLI's built-in default; users can enter any available model ID/alias. Effort is an explicit client-specific choice, initially low; unsupported model/effort combinations fail visibly and preserve the draft. Switching clients restores that client's saved choices. Unsubmitted preference fields use the ordinary private draft boundary and require explicit Save AI preferences. Setting a model does not make a network request. Settings mounts these forms only while open and cancels an unfinished connection test when dismissed. Test agent connection sends a small fixed prompt using the saved configuration.

`HeadlessAgentClient` discovers the fixed CLI name through PATH and conventional local/Homebrew/nvm installation directories, with no shell evaluation or arbitrary renderer executable path. Prompts travel over stdin. Every request gets a temporary working directory unrelated to the project, removed on success, failure or cancellation. Claude uses print JSON, safe mode, empty built-in tools and MCP configuration, disabled hooks, no session persistence and explicit model/effort. Codex uses ephemeral JSON events, read-only sandbox, never approvals, ignored user config/rules, strict configuration validation, no project instructions, disabled shell/local-image/browser/computer/image-generation/code-mode/apps/hooks/plugins/multi-agent/memories/web search and skipped host skill discovery. Agent authentication stays with the CLI; enterprise-managed policies may still apply. These restrictions are for internal suggestions, independent of the normal copied/opened skills workflow. A card drag never launches a headless agent.

Main bounds total stdout/stderr and final text, enforces a two-minute deadline, terminates the process group on cancellation and escalates to SIGKILL after 500ms. It removes Electron runtime/coverage and inherited agent-session environment flags. Raw CLI diagnostics never reach renderer errors because they can contain tokens or prompt text. Missing executable, failed sign-in/model access, timeout, cancellation and invalid/incomplete results leave forms intact. Codex requires a completed turn and final agent messages; failed/error/tool items are refused. The one known diagnostic emitted before a turn when the execution host is deliberately disabled is ignored only on an exact message match; it cannot mask a mid-turn error or tool action. The installed CLI uses canonical feature switches for local images and browser/computer/code execution. Strict configuration rejects unknown restrictions instead of silently ignoring them. Claude requires a successful non-error result. Numeric progress reports only final suggestion character counts, without exposing raw output.

Project AI context comes through the correlated utility-query boundary, selected by record identities. The collector chooses only known public planning fields and bodies: selected profile answer, action/run, completed release members and proposal. Source files, repository docs, private queues/journals and unknown record fields are excluded. Onboarding question descriptors are validated configuration/UI text; user draft notes are explicit input. The main prompt boundary rejects outside/private/traversing source paths and caps total text. Each feature retains its version-1 prompt and recorded fixture responses.

Privacy previews show the selected planning text, client, model and effort. Their fingerprints bind the exact context and all three agent preferences. Generation checks the fingerprint before execution and again before returning results. One request may run per window. Cancellation and closure target that window; changing the client or AI preferences cancels active internal calls. Suggestions are parsed against feature schemas and template answer types before entering editable drafts. Restored source-backed reviews recheck their generation fingerprint before Use; pending requests are never replayed.

Native modal events remain scoped to their own dialog. AI fills editable fields, never auto-saves, approves or runs implementation. Profile answers become confirmed only through Save answer/Create planning folder. Follow-up questions remain editable local prompts. Summaries are labeled drafts. Release-note drafts open the existing Plan description editor for explicit saving and cannot authorize a proposal, commit or tag.

`task-title` returns a nonempty title bounded to 160 characters. `task-capture` returns a title, source-preserving Markdown description and one of the seven action types. Both use only supplied form text. Normal preserves its description/type; Agentic metadata remains in the private draft until explicit Save. Selected source or configuration changes require renewed preview/generation where appropriate.

Tests use real temporary executable fixtures for the external CLI boundary. Native/UI tests substitute fixed executables only through unpackaged-only `VOIDRA_TEST_CODEX_CLI` / `VOIDRA_TEST_CLAUDE_CLI`; packaged apps ignore them. Test fixture HTTP servers only coordinate those fake CLI responses; production makes no provider HTTP requests. Real-account smoke evidence is kept separately from deterministic CI checks in [verification](../verification/headless-ai.md).
