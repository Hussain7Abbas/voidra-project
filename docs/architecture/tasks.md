# Tasks and project release identity

[Architecture index](Intro.md) · [v1.1.0 phase](../../plan-v1.1.0/phase-01-task-contracts.md) · [Existing action workflows](backlog-actions.md)

Tasks is the default work surface. The primary Backlog and Actions navigation entries are removed; their ideas/actions retain their original IDs and open as Tasks details. Run retains its command surface; Waiting for you is the retained bottom panel. No new planning directory or task IDs are introduced.

`projectTasks(project)` projects validated idea/action records into Backlog, TODO, In progress, Review and Done. A promoted idea with an existing action appears once, retaining the idea ID as provenance. Unresolved promotion links remain visible rather than disappearing. Child tasks retain parent IDs, and rejected/cancelled records remain available through an explicit filter. Invalid filename/duplicate identities are excluded using the package diagnostics.

Board columns describe organization and progress, not permission. Initial ready actions, including a Docs action whose first lifecycle stage is Implement, appear in TODO. Runs, running/failed state and Verify indicate In progress; Review and terminal completion retain their own columns. Human checklists remain supported. Projection never changes stage, answers, approvals or stored files.

The utility caches task projections alongside the original records in SQLite index version 8. Prepared operations retain the prior complete cache, and task reads use that cache as well. Deleting, corrupting or upgrading the index rebuilds the projection from `.voidra/`; existing persistent undo tables are not part of a routine schema rebuild.

`readProjectRelease(root, path?)` reads only a contained `package.json`, defaulting to the project's `releasePackage` selection or root `package.json`. Reads are bounded to 256 KiB, validate UTF-8/JSON/version, refuse symlink components and nonregular files, and return only path/version/revision/notice. No package contents enter the renderer or AI context. Missing/invalid versions leave existing records and Backlog capture intact.

The Tasks release-source form calls `setReleasePackage` with the displayed metadata hash. It stores the per-project path in `.voidra/voidra.json`, preserves unknown fields, refuses active/unfinished operations and participates in persistent undo. The utility watches the selected package as well as the default root file, refreshing version metadata when external tooling changes it. Changing the selected source never retags existing tickets.

Existing projects opt into task tracking through a displayed migration preview. Fresh initialization enables task tracking and private Actions intent atomically. A valid package version places Bootstrap in TODO; without one it stays in Backlog with a null release until a real version source is provided and the task is explicitly moved. Initialization never invents or writes a package version. `previewTaskTracking` binds package bytes, metadata and task records; `enableTaskTracking` rechecks that revision and the package under the writer lock, then writes the upgrade in one recoverable group. Metadata gains `taskTracking: 1` and `requiredVoidra: 1.1.0`. Active work receives explicit target-version metadata; completed/cancelled/rejected history remains byte-identical, and explicit Backlog null assignments survive. Promoted sources remain linked and guarded. App upgrade writes participate in persistent undo; CLI migration uses `migrate --tasks --dry-run --json` followed by the exact returned revision.

`newTaskFields` centralizes defaults for shared action/idea creation, promotion, profile/assumption changes, Sync suggestions, Release actions, architecture slices and runtime human blockers. With tracking enabled, new work gets the current package version; unavailable versions permit Backlog capture. Explicit TODO requires a release, active tracked actions require placement/target metadata, and Backlog tasks cannot enter the runnable queue. Target release remains distinct from historical `releasedIn` membership. Legacy projects keep their previous contract until explicitly upgraded.

The published app/library/reader/skills are aligned to 1.1.1. The task contract begins at reader 1.1.0; the retained 1.1.0 tag is unchanged and unpublished after hosted harness-readiness checks. Fresh initialization enables tracking atomically; existing legacy projects retain exact migration. Actual old-reader refusal, both-client acceptance and public downloaded-app verification are recorded in [final evidence](../verification/v1.1.0-p10.md).

`moveTask` accepts the displayed card revision and permits unstarted ready actions to move between Backlog and TODO. It preserves body, stage/status, approvals, blockers and assigned releases; only a missing TODO release defaults to the selected package version. Typed idea moves use reciprocal promotion. Other columns remain driven by runs and human decisions. Archives and Profile drafts cannot use organization to bypass their gates. TODO placement does not imply queue eligibility: blockers, questions and approvals still control execution.

The board exposes a dedicated pointer grip and left/right arrow movement, plus visible Backlog/TODO buttons, through the same classified persistent undo boundary. A gesture captures the original task/revision and retains it across refresh; stale drops refuse instead of silently taking a newer revision. Escape or pointer cancellation abandons the gesture. Hover only changes column feedback; cards are memoized and indexed/grouped once, and edge scrolling uses animation frames without whole-board updates on every pointer event. Each column scrolls independently, with contained offscreen rendering. Source metadata and absent run/planning locks are guarded by grouped writes. Human checklist/aggregate completion and explicit Profile activation fill missing target releases before leaving Backlog, or refuse when no valid release exists. A manually edited draft remains ineligible even if its stored placement says TODO; only explicit Profile activation can activate that draft through the queue. Legacy draft eligibility stays unchanged before opt-in. Research follow-up ideas use the same defaults as other creation paths. A null release on untouched legacy history is never a fabricated release assignment.

## Release filtering and details

The board defaults to All releases so legacy and migrated work remain visible. The Release dropdown also offers Current with the actual package version, deduplicated historical/assigned versions in numeric order, and Unassigned Backlog. A missing current package disables Current; it does not hide saved historical assignments. Type, status, assignment and archive filters are view state only. They do not change task records or the global run queue.

The board stays mounted while a card detail is open, preserving its filters and local draft context. Watcher-driven query invalidation keeps the shell’s active workspace query current; mounting a detail does not perform a redundant read. A card opens its existing action detail or Backlog idea detail, preserving Markdown, plans, questions, approvals, linked commits, blockers and legacy human checklists. Back to Tasks returns to the board. Each child card links to its parent. An untyped idea requires choosing its action type through its existing promotion form before TODO; a typed idea uses the shared reciprocal promotion operation. Illegal progress/review/completion moves show the shared gate explanation and a button to open the task’s steps. No drag operation invents a run or accepts work.

Release source and migration controls live in the native Release settings disclosure. Its close action flushes release-source drafts before hiding; a failure keeps it open. After a move, focus returns to the moved card unless the user focused another control. If filters hide the card, a status message explains the destination and focus returns to the release filter.

### v1.1.0 Actions sequence

The [versioned private intent/queue contract](../format/queue.md#versioned-actions-intent-reader-110) separates visible work from consumable execution requests. TODO creation/moves and domain/runtime producers group enrollment with their source write; returning to Backlog or reaching a terminal projection removes membership. Reorder preserves pending-token membership and compares the complete global order, both private hashes and source revisions. The service caches the complete sequence with tasks in index version 8, retaining the prior snapshot during unfinished writes. Run receipts persist ordering consumption without making clone validity depend on private local files. Both standalone clients use the same first-eligible selection; existing gate/ownership/assignment checks remain authoritative.

P07 keeps the filter controls in one independently scrolling row and reduces introductory chrome so narrow centers retain board space. Labels and keyboard access remain intact; all filters still affect only the board, and source disclosures still flush their draft on close.
