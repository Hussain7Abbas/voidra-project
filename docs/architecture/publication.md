# Packaging, update notices and publication recovery

[Architecture index](Intro.md) · [Version/checkpoint ADR](../adr/2026-10-14-release-versions.md) · [Icon review](../icon-review.md)

The desktop uses the reviewed original Ink & Iris icon, exported as PNG/ICNS by pinned Sharp and iconutil. Electron builder creates unsigned arm64 DMGs with automatic publication explicitly disabled by both publish=null and --publish never. The null configuration also prevents inferred update metadata in token-bearing CI; Voidra uses its own main-owned release notice. The DMG smoke mounts read-only, copies with ditto, detaches before launch, and starts the independent copy with fresh data. It also verifies sandboxed IPC, native SQLite, unpacked ownership and actual archived skill installation. The built minimum macOS version is 13.0.

Main alone checks this repository's latest public GitHub Release at packaged startup and once per day. Development has no automatic request unless an unpackaged-only localhost test endpoint is supplied. The request includes no project data or key. Responses are bounded; draft/prerelease, malformed, older/equal and offline responses create no notice. The download URL must match the canonical repository/tag and main rechecks the displayed version before opening it. Notes render as plain text. Settings updates immediately while saving, persists opt-out, and aborts/hides active notices when disabled.

One stable X.Y.Z aligns app, public library/reader and all six skill declarations. Their validation commands pin that exact library version; intake instructions use the writer's current version. Format and template versions remain independent. Alignment also updates the newer-format golden diagnostic’s declared reader version while preserving its required version, unrelated diagnostics and unknown fields; it does not regenerate the fixture catalog. `make release VERSION=X.Y.Z` refuses dirty source, prepares version changes, rebuilds the aligned library before generators load its workspace export, regenerates, runs quality and the full desktop suite sequentially, checks exact expected changed bytes, commits selected paths, creates a new immutable tag and pushes. Existing tags retry their original workflow instead of shipping newer source under the same version. Publication status lives in ignored `.cache/releases/<tag>/`.

The tag workflow checks quality/Electron workflows, builds/stages the DMG and genuine npm archive, and saves checksums plus a public release manifest. Original bytes are retained in a source-bound CI artifact before any GitHub publication. A retry restores them by tag/source, then validates and smoke-tests them. Fully published assets remain a fallback after CI-artifact expiry; an incomplete draft without its original checkpoint stops. Rebuilding a nondeterministic DMG over a stored checksum is never a recovery step.

GitHub’s [release-by-tag endpoint](https://docs.github.com/en/rest/releases/releases#get-a-release-by-tag-name) exposes published releases. After 404, the adapter uses [gh release view](https://cli.github.com/manual/gh_release_view) to locate a draft, requires the exact tag and a numeric API endpoint under this fixed repository, then reads that draft by ID. Transport and permission failures remain errors. Compatible private publisher repairs may complete an already checked retained stage using only its original source/bytes; new app/library/skill content requires a new tag.

The GitHub adapter creates a draft, verifies each uploaded asset by actual bytes, rechecks source/notes, and makes it public only after all files agree. It dispatches the separate exact-tag npm workflow. That workflow downloads the same archive and publishes using GitHub OIDC/provenance, with no stored npm token or local-token fallback. Registry verification binds archive integrity, package subject, repository/workflow/ref and provenance source SHA. Confirmation allows up to a minute for registry/provenance propagation, never republishes an already visible version, and reports pending confirmation separately from a mismatch. A mismatch stops without overwriting a version.

The local coordinator waits for those external checkpoints, records partial failure honestly, then extracts the exact tagged skills/templates and calls the P14 distribution tool through existing Hussain7Abbas authentication. Failure monitoring uses the newest workflow run from the current request, so a completed failed attempt cannot abort a newly dispatched retry. No cross-repository CI secret is required. GitHub, npm and skills are separate durable destinations; no cross-service rollback or atomicity is claimed. Same-tag GitHub/npm runs are serialized. Test failure variables apply only to the explicitly named test tag and inject before GitHub staging or after GitHub succeeds.

P15 verifies actual immutable GitHub/npm/skills publication and recovery for the retained 0.2.2 preview, including OIDC provenance. The failed v0.2.0 and v0.2.1 candidate tags remain immutable. P17 completes the full 1.0.0 matrix, user-reported VoiceOver, guarded live publication and final downloaded-app verification. An initial hosted refresh assertion timeout is retained alongside the successful unchanged-tag retry; npm’s deferred registry processing is resolved by confirmation of its original immutable publication. Fixture tests remain distinct from these live results.
