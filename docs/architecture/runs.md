# Standalone runs and human review

[Architecture index](Intro.md) · [Ownership ADR](../adr/2026-10-13-run-ownership.md) · [Skill procedure](../../skills/voidra-go/references/runtime.md)

`tools/run-engine` is a Node-only coordination library. Its generated standalone bundle lives inside `skills/voidra-go`; the agent can run it with the app closed. It validates through the public format package, persists consumed records, checks host/PID/start/token ownership, and checkpoints before commit/finalization effects. Private checkpoints live in `.voidra/local/run-checkpoints/`, while run results stay with each action.

The app holds its previous complete index during unfinished grouped operations and prepared/unfinalized run checkpoints. Reviews compare every presented action-directory file to the displayed fingerprint, then carry those hashes through the grouped write. Reject preserves feedback and follows each type’s rework target: implementation types to Implement, Research to Discovery and Release to Plan. Accept finishes implementation/Research; Release stays in Review pending agent finalization. All decisions refuse active or unfinished runs. See [questions, gates and inbox](questions-gates-inbox.md).

The app provides a recovery command for the agent. Git-index reconciliation remains in the standalone runtime: the app never creates an implementation commit or modifies its Git index as a recovery side effect. Prepared file conflicts stop recovery and retain outside edits. Metadata can be completed or rolled back through the format package's explicit operation recovery.

Development linking uses the documented project locations `.claude/skills` and `.agents/skills`. `make skills-link PROJECT=/absolute/project` links real skill folders there; the default target is this repository. Existing conflicting contents are preserved. The bundle and local format reference are deterministic and checked by `make gen-check`; skill frontmatter, length and relative resources are checked by `make lint`. No authenticated agent runs in CI.

P08 extends ownership to Feature, Bug, Improvement/refactor, Profile change and Research. Planning proposals are prepared by the installed template architecture procedure and published with the active run token in one operation with the stopped run and lock release. Question history survives later rounds; only explicit delegated choices may receive an agent option, reason, identity and timestamp. Plans stop for exact-byte human approval. Research produces findings, a recommendation and new backlog ideas, with no implementation commit. Human-only steps create an unchecked checklist and a dependency on the active action.

Implementation checks ownership, approved plan bytes, consumed inputs and overlapping pre-existing user changes before each edit batch. Successful verification reports both repository standards and plan review. Preparation advances through the declared lifecycle to Review; the separate-index commit still leaves unrelated staging intact. Planning-only runs use the same helper with `mode: plan`, compare repository snapshots, HEAD and tags, and cannot prepare or commit implementation. Glossary additions preserve existing bytes and use the contained grouped writer during Discovery.

The CLI returns only action/run identifiers, ownership token, paths, phase and mode. Full source and input fingerprints remain in private checkpoints. A stale gate in an unchanged sibling action is pending human work; it does not make otherwise valid planning data globally read-only. Profile change drafts activate only through an explicit app queue decision carrying the displayed action hash, recording actor and time.

P09 queue editing and runtime startup share `queueDecision` from the format package. The validated `replace-queue` bridge carries the displayed queue hash and action hashes to `replaceActionQueue`; the service checks recovery state. Queue mutations guard planning inputs and absence of a run owner, and runtime startup rechecks eligibility when consuming the next action. The Run picker supports keyboard add/remove/reordering and keeps live ownership/recovery messages.

Git history is read with argument arrays and trailer formatting. The snapshot retains tagged action commits, follow-up commits and untagged history for Sync. The main process opens only a current commit hash from the service and a validated GitHub remote URL; the renderer never supplies an external URL.

The Run screen also previews new, modified and deleted shared planning files. A displayed snapshot and explicit selected paths authorize `Commit planning changes`; local files remain excluded even if force-tracked. Git paths are literal, including unusual filenames. The Node-only planning helper stages selected files in a private index, registers new paths before `commit --only`, and journals the operation under `.voidra/local/planning-commits/`. Failed hooks leave the main index untouched. On success it copies the main index under an exclusive Git lock, reconciles only unchanged selected entries, and preserves unrelated staging. A unique `Voidra-Planning` trailer identifies an existing commit after process death; recovery does not duplicate it. Concurrent selected index edits are retained and reported after successful commit. Pending planning operations prevent new agent runs. Root-only planning commits reject folders inside another Git repository. Intake glossary/instruction changes need a separate explicit agent/Git commit. Nothing is pushed.

Starting unassigned agent work records the runner’s configured Git name/email in the same durable action/run write. Existing assignments survive. Missing identity is a setup error before unassigned implementation starts; Discovery/Plan may remain unassigned.

The generated 1,000-action fixture is benchmarked with a real Git repository and fresh app-data/index directories. P09 records cold opening, board filtering/restoration, action detail and rebuild timings in its verification evidence.

New-project Discovery/Plan can run while Git is absent. Checkpoints bind repository presence, source, HEAD and tags, so creating Git during planning is an outside effect. Existing Git must resolve to the canonical selected worktree root; a subfolder is refused before ownership or planning writes. Only Feature Bootstrap Go implementation with exact current plan approval initializes a missing repository, after durable ownership and consumption. The normal result commit is the first commit and carries its action/run trailers; no synthetic setup commit or remote is created. Other non-Git implementation is refused. Existing non-planning files remain protected as pre-existing work. The first Bootstrap commit also saves the initial public planning baseline (metadata, recognized shared records, planning README and ignore rules). Its hashes are frozen at startup and checked before preparation; private local state and pre-existing source are excluded. A fresh clone must validate without relying on untracked planning files.

### v1.1.0 Actions sequence

The [versioned private intent/queue contract](../format/queue.md#versioned-actions-intent-reader-110) separates visible work from consumable execution requests. TODO creation/moves and domain/runtime producers group enrollment with their source write; returning to Backlog or reaching a terminal projection removes membership. Reorder preserves pending-token membership and compares the complete global order, both private hashes and source revisions. The service caches the complete sequence with tasks in index version 8, retaining the prior snapshot during unfinished writes. Run receipts persist ordering consumption without making clone validity depend on private local files. Both standalone clients use the same first-eligible selection; existing gate/ownership/assignment checks remain authoritative.

## Workflow runs (reader 1.2.0)

Explicit workflow tasks use the shared run-kind contract: Planning is source-read-only even for Docs/Research, TODO is idle, In progress implements and Review checks QA/security separately. Planning-only mode may plan ungated workflow tasks but cannot publish quality or implement them. Questions and exact plan approvals retain their existing human gates. Implementation finalization queues Review automatically.

`publishQuality(root, token, report)` requires a live owned quality run, unchanged source/HEAD/tags and all consumed inputs, plus a completed implementation or Research finding. Nonempty QA and security checks carry concrete evidence. Passing checks atomically link the quality run and complete the task; failures return idle TODO; missing requirements append questions and return Planning. Reports and original approval/review/run history remain available. Quality never repairs source or commits. Release actions and legacy tasks keep their human acceptance semantics.

An existing repository must commit its reader 1.2.0 metadata upgrade explicitly before implementation/quality. This prevents committing new-format action data over an unsupported cloned metadata baseline without staging unrelated edits.

## Parent repositories with Git submodules

The selected root owns `.voidra/` and the run lock. `submodules.ts` enumerates index gitlinks recursively and records each child repository's initialized state, HEAD, tags, parent and staged/committed pointer. Both `.git` files and old embedded `.git` directories work; Git metadata is excluded from source snapshots at every depth. Startup enumerates changed files within their actual repositories instead of hashing a dirty gitlink directory. Existing user edits and selected index changes remain protected.

Implementation reports exact parent-relative files, for example `components/extension/src/title.ts`. The runtime refuses a directory, symlink, an unregistered embedded repository, nested planning files, an uninitialized child, an existing child Git operation or pre-existing pointer changes in the selected ancestry. It never initializes/fetches children. Unrelated dirty files and staging in root and child repositories remain intact.

Preparation records per-repository selected index entries and base commits. Commit persists the intent before effects, commits deepest children using private indexes, then records their gitlinks in each parent up to the root. Every commit has the same action/run trailers; final run metadata records child paths and commit receipts. Recovery after a verified dead owner reconciles each receipt and resumes the remaining chain without duplication. An unfinished child commit intent cannot be abandoned through `fail`; preserve it and use explicit runtime recovery. Changed prepared bytes, HEADs/tags or selected index conflicts stop reconciliation and retain outside work. Finalization reconciles only selected real-index entries before releasing ownership.

Planning and QA compare child source snapshots, HEADs, tags, topology and pointers as well as root state. They create no child commits. The helper never pushes; publish child commits before parent pointers through the project's normal release process. A commit chain across repositories is recoverable but cannot be one atomic Git commit.

All six skills include `scripts/voidra.mjs`, a bundled public-format CLI limited to `check`, operation `recover` and `version`. New planning README/intake pointers use this matching checker instead of downloading a version from a package registry. Runtime recovery still uses `runtime.mjs recover`; the validator's `recover` handles format grouped operations.
