# Onboarding and the project profile

[Architecture index](Intro.md) · [Template contract](../format/template.md) · [Intake skill](../../skills/voidra-init/SKILL.md)

The utility process loads bundled templates through the shared package. Bridge objects strip execution-only template fields and never import Node/YAML into preload. Invalid template entries are skipped and their paths/fields are shown; unknown or missing project template versions leave profile answers readable and editing disabled.

A folder without planning data is classified as existing code if an unlinked known manifest or at least one source file is found within six directory levels. Known manifests include package.json, go.mod, Cargo.toml, pyproject.toml, requirements.txt, pom.xml, build.gradle, Gemfile, composer.json and project.godot. Source suffixes include JavaScript/TypeScript, Python, Go, Rust, Java/Kotlin, Swift, C/C++, C#, Ruby, PHP and GDScript. Dependencies, Git, planning data, generated/build output and virtual environments are ignored. Evidence is a relative filename; detection reads names, not file contents.

New folders pick a template, answer known questions and create a complete profile plus a Feature Bootstrap at Discovery. Optional unanswered fields stay open; required manual answers are checked in both the form and shared initializer. Existing code shows the /voidra-init and $voidra-init commands or permits manual intake; it creates no Bootstrap. The app writes only planning files. Initialization builds a complete checked .voidra in a temporary sibling project and renames it into place, refusing an existing planning directory and cleaning staging on failure. The rename follows optimistic existence checks, not an OS-exclusive compare-and-swap against hostile concurrent replacement.

The standalone intake helper records every answer as inferred with an existing unlinked source file. Unknown values are null with an explicit evidence gap. It preserves existing GLOSSARY.md and instruction text, appends the Voidra pointer, and gives both agents an instruction entry point. If only a full CLAUDE.md exists it appends there and creates an AGENTS.md pointer to those existing rules. A CLAUDE.md that only imports AGENTS.md is preserved. This reconciles the phase's preferred instruction target with the vision's requirement that both agents see the rules. No Git command is executed.

Profile changes compare the displayed block hash against disk. Confirming an inferred answer records the actor/time without a draft; changing a confirmed value creates a linked draft Profile change with the old/new JSON values. Draft Profile changes cannot be consumed before review. P04 added profile rows as a disposable cache; the current P07 cache version is 4; unfinished grouped writes hold all prior complete rows. Active/recoverable runs or file errors block profile edits.

Forms reuse Ink & Iris Field/Dialog components, semantic radio/checkbox groups, visible labels/help, optional free-text choices, native constraints and explicit answer-status badges. Required input feedback is synchronized with aria-invalid after interaction. Inferred nulls must be filled before confirmation. P05 approved final template content under delegated review. P07 places inference confirmation in Waiting for you; P08 adds architecture/lifecycle execution.

Intake creates .voidra atomically; glossary/instruction steps are individually checked afterward. An outside edit to an instruction stops pointer work and leaves a valid inferred profile for inspection. There is no automatic overwrite or rerun over an existing profile. Its failure report must identify that partial state. Standalone generated assets resolve relative to their own copied skill directory, independent of the development checkout.
