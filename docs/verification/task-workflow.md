## Accepted behavior and implementation

The user's clarification selects copy-and-open client guidance rather than a headless drag, inserts In progress as the implementation trigger, keeps TODO as fully planned inventory, and automatically completes passing QA/security. Planning questions and exact plan approvals remain human gates. New workflow fields require reader 1.2.0. Legacy tasks and exact Release acceptance retain their original behavior until explicit workflow adoption.

Capture creates Backlog work. Planning owns edge-case questions and plans/slices; answered questions requeue planning. Gated approval or an ungated written plan parks TODO. In progress queues implementation; finalized results queue a separate source-read-only Review. Owned quality results bind source, HEAD/tags and consumed inputs: pass→Done, failed checks→TODO, requirements questions→Planning. History is appended, not replaced. Research findings can be reviewed without an invented implementation commit. An existing repository explicitly commits the metadata upgrade before implementation/QA, preserving fresh-clone validity without staging unrelated edits.

Task deletion is a reversible expected-revision soft deletion, protects unfinished relationships and pending work, preserves canonical history/references and removes queue membership. Documentation integrates Explore/Glossary/Decisions with retained state and keyboard tabs. Actions incorporates queue, planning commit and recovery controls. Sync is a yellow top notification. Splitter layout occupies 1px; wider pointer targets overlay panes. Go/Sync/recovery/init guidance copies the selected client's command and opens that app without submitting it.
