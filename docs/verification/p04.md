## Delivered

The shared package validates plain YAML templates, preserves unknown fields, rejects duplicate IDs/choices, invalid examples, unsupported formats and lifecycle overrides that lose required gates. Catalogs skip broken entries with file/field diagnostics. General 0.1.0 is starter content containing all five supported question types; final questions and general 1.0.0 require P05's named review.

New-project onboarding creates a complete checked profile and Feature Bootstrap through an atomic planning-directory rename. Existing code is detected from documented manifest/source names, ignoring dependencies, build output and symlinks. Existing-project onboarding offers each agent's intake command or manual completion, with no Bootstrap. Templates are bundled in the packaged app. Profile screens preserve source/status distinctions, support optional answers and other choices, confirm inferences with actor/time, and create linked draft Profile changes for changed confirmed values. Writes compare the exact displayed block hash; active/interrupted work and invalid data block editing. Draft Profile changes cannot be consumed before review.

`voidra-init` and its generated standalone helper work without the app. Every inferred answer names an existing unlinked project source. It preserves source code, existing glossary and instruction text; creates a glossary only if absent; adds the instruction pointer; and executes no Git command. Full CLAUDE-only rules get an AGENTS.md entry pointing to them so both agents respect the project. An import-only CLAUDE.md remains exact. New workspace APIs are bundled in the app/skills; they are not yet in the published 0.1.0 API. That published CLI validates the resulting format-1 files.

P04-08 records a follow-up to P03: generated bundles resolve assets relative to their own copied skill directory. Tests copy both skills to arbitrary temporary locations and exercise actual intake and run-start ownership without the development checkout. Runtime/reference/template copies are checked for staleness and both skills pass metadata/link lint. Only their exact generated JavaScript files are excluded from formatting/deprecation scans; authored scripts remain scanned.

## Boundaries

Source detection is documented heuristics, not language analysis. Inferences remain guesses until confirmed; null inferences require an answer before confirmation. A missing project template version leaves editing unavailable. The starter template's architecture skill is a future P05 reference; architecture dispatch and executing lifecycle overrides arrive in P08. Existing minimal P03 planning folders without a template remain readable and have no automatic profile retrofit.

The initial directory rename uses cooperating-writer existence checks, not an OS-exclusive compare-and-swap against hostile replacement. Intake's glossary/instruction steps are separate checks after atomic profile creation; an instruction conflict leaves a valid profile for inspection and is reported rather than overwritten. The standalone helpers do not commit. P07 later merges inference confirmation into the inbox; P10 adds undo. Axe/VoiceOver and unsigned-packaging limits remain as in P02/P03.
