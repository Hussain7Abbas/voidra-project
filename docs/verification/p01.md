## Implemented contract

- Format 1 specification: each record/file type has an example, with the Markdown/frontmatter ADR, explicit versions, helper commands and API boundaries.
- Byte-stable UTF-8 Markdown/YAML/JSON, BOM/CRLF/empty bodies, unknown fields and nested comments. Conditional schemas for 13 structured record kinds plus guide/ignore text schemas; file/field/line diagnostics.
- Collision-checked random Crockford IDs, all seven lifecycle definitions, template invariants, question/plan/review gates and Release commit/tag evidence. Pure transitions use validated current context.
- Read-only cross-record checks: identities, references, cycles, children, queue, questions, lifecycle/status contradictions, incomplete frontmatter, conflicts and unfinished operations. Metadata gates newer formats before other records.
- Exact-byte plan hashes, displayed revision rejection, stale implementation approval routing and Release Review fingerprints. Previous plan approvals and replaced Release review decisions are retained.
- Validated grouped operations, same-directory flushed temporary files and atomic rename, expected-hash checks, restricted paths, exclusive cooperating-writer lock and local durable before/after journals. Explicit complete/rollback recovery and completed receipts prevent duplicate replay. Outside edits cause conflicts.
- Built CLI with human/JSON output and exits 0/1/2. Helpers share the public package implementation. Read-only `plan` supplies the revision needed by `approve`.
- Explicit unreleased prototype format-0 migration: dry-run, real migration, repeat no-op and interruption recovery/rollback without newer-version downgrade. Legacy and unknown fields survive.
- Native zod JSON Schema export, generated docs/shared skill references and missing/stale/orphan checks in `make check`/CI. Actual executable skills and template content are outside P01.
- 33 committed catalog cases, including broken kinds/cross-file cases and a busy project. `new-project` is minimal valid format data until P05 replaces it with actual general-template output. A script generates and validates 1,000 actions outside the repository.

## Failure evidence

Real temporary files, without mocked filesystem calls, cover each temporary-write/flush/rename and journal replacement boundary for both records, plus lock, validation, prepared-journal, preflight, file-applied and commit checkpoints. Tests kill a real writer child with SIGKILL, preserve the original on a real failed rename, recover its dead-owner lock, repeat recovery, roll back file creation/deletion, refuse a live owner, preserve outside edits before/after preflight and reject traversals/symlinks/code/reserved paths. Each plan file is independently changed with whitespace; approval becomes stale and an old displayed revision fails. A change between approval validation and writing also fails its expected hash.
