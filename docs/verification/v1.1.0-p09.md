## Delivered behavior

The release wizard selects completed work, offers Xeploy-backed stable Bug fix/Minor/Major/Custom versions and Markdown notes, then requires an explicit version-labeled Keep/Move choice for the exact shown current-version Done subset. Back, cancel, close and restart retain the whole private draft, including invalid partial versions and original member/package hashes. A stale package blocks submission without renewing that saved context. Create writes planning only. The selected coding client prepares the exact Review proposal before source, commit or tag effects.

The utility and standalone `release-options` command share a read-only adapter. Pinned Xeploy 1.4.2 was verified against registry metadata and its [published source README](https://github.com/Hussain7Abbas/xeploy/blob/7d20192221f9dbf3bec8026872515ebcbe7151c2/README.md). Registry integrity: `sha512-AetkZs2oxkks7ZsdspbtAOQZTW6r/I6tQvU479ey73r/iHEWH5watiBYDIu/9j7L2I1b4KNlUqqvFWhiqjSN1Q==`. The applicable bump question uses its exported API; its interactive deploy/merge/push flow is never invoked. Safe canonical custom versions must advance current. The existing immutable publication pipeline remains.

`releasePreparation` binds the chosen package path/current version/hash, proposed version, bump, choice and exact current-version selected ticket IDs/hashes. It participates in the structured Release fingerprint and is shown at Review. Both public approval paths and accepted runtime startup refuse changed source/ticket context. Preparation checks the selected package contains the accepted next version. The checkpoint binds the same preparation. Finalization atomically changes targetRelease only for the shown Move subset; Keep preserves it. Both modes retain immutable releasedIn membership, preventing duplicate publication. Historical assignments and human checklist semantics remain.

The browser/preload import only the Node-free `voidra/release-preparation` schema subpath. The standalone guide uses the same read-only Xeploy preview and asks missing decisions through questions. Changed proposals need fresh exact acceptance; no agent approves its own gate or retags records manually.
