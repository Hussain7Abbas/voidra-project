# Meta repositories and matching offline validation

Direct source follow-up requested 2026-10-18 after a real parent/submodule project failed before run registration. The original startup called `readFile` on a dirty submodule gitlink directory and raised `EISDIR`. A regression reproduced that exact failure before the fix. Merely skipping the directory exposed the next failure: parent Git cannot stage an exact file inside a submodule. The runtime now owns a recoverable commit chain across the selected repositories.

## Implemented behavior

The parent owns planning, consumption and the run lock. Recursive index-gitlink discovery supports initialized and nested submodules, `.git` files and old embedded Git directories. Changed-file snapshots inspect each owning repository and exclude Git metadata at every depth. Unrelated dirty/staged user files remain protected. Exact root-relative child files are guarded; uninitialized children, unregistered embedded repositories, existing child Git operations, nested planning edits and pre-existing pointer changes receive explicit refusal. No automatic initialization, fetch or push occurs.

Preparation freezes selected files, per-repository bases and selected index entries. Persistent intent precedes deepest-first child commits and parent pointer commits. Each commit carries the same action/run trailers; final run metadata retains child receipts. Explicit recovery after verified owner death reconciles an already-created child commit and completes the remaining parent work without duplication. An unfinished child commit intent cannot be abandoned through `fail`. Selected index conflicts and outside source/HEAD/tag/pointer changes are retained and stop work. Planning and QA remain read-only across child repositories.

Every skill now includes `scripts/voidra.mjs`, compiled from the matching local format package, with `check`, grouped-operation `recover` and `version`. Skills and newly generated planning pointers use this offline checker. The six payloads are generated and participate in the existing hashed installer/distribution protection. Legacy generated instructions naming the same registry validator version can use the equivalent bundled checker without editing the project’s instructions. Runtime recovery remains separate from grouped-operation recovery. This fixes the dependency on an unpublished registry version without downgrading validation or changing publication versions.
