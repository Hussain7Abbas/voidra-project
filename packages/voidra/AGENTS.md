# Voidra format package

Extends [root instructions](../../AGENTS.md). This package is the shared contract for the app and skills; keep runtime code free of Electron, UI, git side effects and authenticated agents.

`task-view.ts` owns the pure unified task/card projection; board columns never grant lifecycle permission. `project-release.ts` reads contained project package versions with bounded UTF-8/JSON handling and no source-content output. Package-source selection uses displayed project metadata hashes, preserves unknown fields and refuses pending work. Keep [Tasks architecture](../../docs/architecture/tasks.md), format/API docs and references synchronized.

`task-tracking.ts` owns the exact-preview opt-in migration; `task-metadata.ts` supplies creation defaults to all shared/runtime producers. Opt-in requires reader 1.1.0, explicit active-record metadata and a non-null release outside Backlog. Preserve legacy completed history and explicit Backlog nulls. Backlog actions cannot be queued. Package version changes never retag existing records automatically. Use the guarded shared helpers; do not silently repair metadata during reads.

- `src/index.ts` exports public helpers; `src/cli-entry.ts` is the thin executable adapter. Local imports use `.ts` and build to `.js` under ignored `dist/` with declarations.
- `src/records.ts` preserves bytes and YAML node comments. Schema/body checks belong in `schemas.ts`; whole-project rules belong in `project.ts`; disk mutations use `writer.ts`. Lifecycle transitions remain pure. `gates.ts` owns saved question answers, exact displayed review revisions and durable plan-change/review decisions. Approval guards plan/question/action bytes and an absent run lock. `planning.ts` owns backlog/action edits, atomic promotion, checklist/cancellation and guarded aggregate completion. New extended forms advertise the reader minimum; preserve child gates and any parent-owned work/approval. `templates.ts` validates templates, detects code by filenames and owns atomic initial planning creation and expected-hash profile edits; it never reads code contents or runs Git.
- Every object schema preserves unknown keys. The public grouped writer checks expected hashes and the entire intended overlay before a durable prepared journal. Unchanged sibling stale-approval/stale-review gates may remain pending while a different action is approved; changed action directories must resolve their gate, and structural diagnostics always block. Rollback may restore a stale gate without authorizing work. It never writes code files; only an explicit flag permits root `GLOSSARY.md`.
- Tests in `tests/` use real temporary folders. Failure injection belongs at explicit public checkpoints; test actual process death/rename errors as well. Do not mock the filesystem.
- `scripts/generate.ts` produces schemas and shared references. Regenerate with `pnpm gen` whenever the contract changes. `pnpm gen:check` rejects missing, stale and orphan output.
- Backlog capture may store optional proposed type and portable assignee; introducing them advertises reader 1.1.0 without enabling task tracking. Preserve omitted fields on edit and the assignee on promotion. Validation requires that reader minimum for typed/assigned ideas, including after external edits or undo.
- `task-move.ts` owns exact-revision Backlog/TODO organization, using typed idea promotion without bypassing gates. Preserve assigned versions, fill missing TODO releases and guard metadata/run/planning locks. Explicit Profile activation and human/aggregate completion must satisfy release requirements atomically; untouched legacy history remains readable.
- `scripts/fixtures.ts` builds the committed catalog and generates a separate large project. `pnpm fixtures` updates snapshots deliberately; do not regenerate expectations to hide a failure. `new-project` is generated through actual approved general-template initialization, with IDs/times normalized for reproducibility. Broken fixtures retain their isolated validation cases.
- Package publication requires passing checks, built-artifact smoke tests and CI. Keep AGPL license, repository metadata and bin entry in the npm archive. npm account access is required; never print credentials.
- Generated planning READMEs pin validation to PACKAGE_VERSION. Public release publication belongs to the exact-tag OIDC workflow in tools/release-engine; ordinary CI and package APIs never publish.

Update the corresponding [format page](../../docs/format/Intro.md), API docs and generated references with every schema/API change. Keep sibling CLAUDE.md as `@AGENTS.md` plus newline.

- Question/rejection/plan feedback retains raw nonblank Markdown; validate blankness without trimming the stored source.

- `queue.ts` owns queue eligibility/reasons and ordered private queue writes, including displayed revisions, explicit Profile draft activation and lock/input guards. Runtime and desktop use this contract rather than duplicating eligibility rules.

- Validation always reports conflicts. Scoped planning writes may preserve unchanged conflict diagnostics from other records, including their existing missing references; private operation receipts retain those diagnostic fingerprints for recovery. Refuse writes into conflicted files, new references to them and newly arriving conflicts. Project metadata must still validate. Shared Markdown files are checked for conflict markers even when their record kind is unknown.

- `withOperationObserver` scopes durable app-history capture to one real project root and asynchronous edit; CLI/agent writes remain independent. Observers prepare changed snapshots under the writer lock before replacement and complete after the durable receipt. `allowEmptyProject` permits only wholly absent shared planning data for undoing initialization; partial projects remain invalid, and the flag persists in the private recovery receipt.

- `knowledge.ts` collects source-linked planning decisions and creates guarded assumption-revisit actions without changing the answer. `documents.ts` reads only root glossary and repository Markdown docs, refuses symlink components and bounds UTF-8 reads. Keep SQLite and UI projections outside the package; report unreadable ADRs rather than silently hiding them.

- `releases.ts` derives eligible selections and creates source-guarded Release actions, reserving work with canonical membership plus a private concurrency token. Structured Release review fingerprints include selected IDs, version/tag and proposal notes; guard the record and member bytes at acceptance. Final status/date bookkeeping must preserve the approved proposal. Legacy forms remain readable.

- releasedMember preserves completed human checklists with releasedIn instead of an agent stage. Structured proposal fingerprints include declared version/changelog paths and commit message. Read the private selection token for expected-hash guarding; it is serialization bookkeeping, not canonical membership.

- `sync.ts` owns source-linked inferred profile updates, confirmed-answer protection and proposal/Sync record grouped writes. Match template value types and original profile hashes. New Sync records advertise reader 0.2.0, name examined commits/proposals and persist record consumption. Git inspection/reachable-history verification stays in the Node adapter. Private selection tokens serialize concurrent writes; never queue or approve proposed work implicitly.

- `action-sequence.ts` separates versioned private intent from pending execution tokens. Compose `withActionSequence` in domain writes, preserving all original expected hashes (including absent-file nulls), locks, unknown fields and consumption. New task upgrades bootstrap both files inside their exact preview. Reorder requires full membership/revisions, preserves tokens and never adds absent dependencies. Keep strict `queueDecision`; versioned startup skips blocked entries, legacy startup does not. Malformed pairing refuses legacy fallback. Run ordering receipts contain hashes, not clone-required private references.

- `documents.ts` owns contained read-only UTF-8 Markdown reads and the bounded public docs/glossary inventory. Refuse linked paths, retain per-file diagnostics and never broaden to private planning or arbitrary source files. The desktop owns disposable visible-text search; no index copies belong in planning files.

- `release-preparation-schema.ts` is the Node-free canonical Release preparation boundary, exposed as `voidra/release-preparation` for browser/preload consumers. `release-preparation.ts` rechecks the contained package snapshot, forward version and exact selected current-version Done subset. Bind preparation to structured Review and validate both approval APIs; preserve legacy proposals and historical target assignments.
